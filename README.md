# Width comparison and formalization

This repository contains the paper as a flattened LaTeX source, the Lean proof
of its main width comparison, and a blueprint for Theorem 1.1. The manuscript
and the Lean proof use different recursive constructions. The blueprint states
the exact scope of the correspondence.

- [Read the blueprint](docs/index.html).
- [Read the paper](docs/paper.pdf), or its flattened [LaTeX source](main.tex)
  with the generated [bibliography](main.bbl).

GitHub Actions compiles `main.tex` with `main.bbl` on every push to `main`,
then publishes `docs/` through GitHub Pages. The published site includes the
fresh `paper.pdf`. Pull requests check that the paper
compiles without deploying. For the first deployment, select **GitHub Actions**
as the Pages source in the repository settings. The site links each checked
declaration to a local Lean source view.

The paper files are generated from the frozen manuscript by
`latexpand --empty-comments`. `main.bbl` is generated by BibTeX, cleaned by
`latexpand --empty-comments`, and loaded by `main.tex`. To compile the export,
run `pdflatex main.tex` twice. BibTeX and the original section files are not
needed.

The Lean toolchain and dependencies are pinned. Run `lake build` and
`lake env lean Paper/Audit.lean` to check the proof and its axiom audit. The
formalized result is `Paper.Hypergraph.main_width_comparison`.

The blueprint HTML is generated by the private export script and included for
reading. To rebuild it here, set up
the Python packages in `blueprint/requirements.lock`, install Graphviz and a
TeX distribution, and run `bash blueprint/build.sh`. The build requires this
directory to be a Git repository. See the blueprint source in `blueprint/src/`.

This directory is generated by `python3 scripts/export_public.py` in the
private working repository. Edit the sources there, then regenerate the
export. The export script preserves a separate `.git` directory here.
